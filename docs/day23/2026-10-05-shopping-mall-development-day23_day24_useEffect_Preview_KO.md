# Day 24 --- `useEffect`와 외부 시스템 동기화

## 핵심 질문

> 컴포넌트는 언제 외부 시스템과 동기화하는가?

## 학습 주제

``` text
render
Effect
useEffect
dependency array
외부 시스템
API 호출
```

## 핵심 개념

`useEffect`를 단순히 다음처럼 외우지 않는다.

``` text
useEffect = fetch
```

대신 다음과 같이 이해한다.

``` text
useEffect
=
React 컴포넌트를 외부 시스템과 동기화하기 위한 도구
```

외부 시스템의 예:

``` text
API
서버
브라우저 API
타이머
이벤트 리스너
외부 라이브러리
네트워크 연결
```

> **팁:** `useEffect 안에서 무엇을 하지?`보다 먼저
> `React 바깥의 무엇과 동기화하려는가?`를 질문한다.

------------------------------------------------------------------------

## 핵심 흐름

``` text
컴포넌트 렌더링
↓
Effect 실행
↓
외부 시스템과 동기화
↓
API 호출
↓
데이터 수신
↓
State 업데이트
↓
컴포넌트 재렌더링
↓
변경된 State를 UI에 반영
```

> **팁:** Day 23의 `Event → State → UI`와 Day 24의
> `Render → Effect → External System → State → UI`를 비교해서 기억한다.

------------------------------------------------------------------------

## render와 Effect의 차이

### render

React가 현재 Props와 State를 기준으로 UI가 어떻게 보여야 하는지 계산하는
과정이다.

``` text
Props + State
↓
컴포넌트 실행
↓
JSX 계산
↓
UI
```

### Effect

렌더링 자체가 아니라 렌더링 이후 외부 시스템과 동기화하기 위해 실행하는
코드다.

``` text
렌더링
↓
Effect
↓
외부 시스템과 동기화
```

> **팁:** UI를 계산하는 일인지, React 바깥과 연결하는 일인지 구분해본다.

------------------------------------------------------------------------

## 기본 `useEffect`

``` tsx
useEffect(() => {
  console.log("Effect 실행");
}, []);
```

기본 구조:

``` tsx
useEffect(() => {
  // Effect 코드
}, [dependencies]);
```

두 번째 인자인 `[dependencies]`를 **dependency array(의존성 배열)**라고
한다.

> **팁:** 처음에는 문법보다
> `Effect가 언제 다시 동기화되어야 하는가?`라는 질문을 중심으로 본다.

------------------------------------------------------------------------

## Dependency Array

``` tsx
useEffect(() => {
  // ...
}, [value]);
```

Effect가 사용하는 반응형 값이 변경되면 Effect가 다시 동기화를 수행할 수
있다.

다음처럼 단순 암기하기보다:

``` text
[] = 한 번
[value] = value 변경 시
```

먼저 다음 질문을 한다.

``` text
Effect가 어떤 값에 의존하는가?
```

> **팁:** 의존성 배열은 Effect가 사용하는 값과 연결해서 이해한다.

------------------------------------------------------------------------

## API 호출과 Effect

``` tsx
useEffect(() => {
  void loadOrders();
}, [loadOrders]);
```

이 코드를 다음처럼 읽는다.

``` text
컴포넌트 렌더링
↓
Effect 실행
↓
loadOrders() 실행
↓
외부 API와 통신
↓
주문 데이터 수신
↓
State 업데이트
↓
재렌더링
↓
주문 UI 업데이트
```

> **팁:** `useEffect = API 호출`이 아니라
> `API가 외부 시스템이므로 Effect에서 동기화한다`고 이해한다.

------------------------------------------------------------------------

## 실제 프로젝트 연결

``` tsx
useEffect(() => {
  void loadOrders();
}, [loadOrders]);
```

핵심은:

``` text
React 컴포넌트
↕
외부 시스템
```

사이의 **동기화**다.

API 호출은 외부 시스템과 동기화하는 여러 사례 중 하나다.

> **팁:** 프로젝트 코드를 볼 때 `loadOrders()`가 어떤 State를
> 업데이트하는지도 함께 추적한다.

------------------------------------------------------------------------

## Day 24 최종 목표

다음 코드를 보고:

``` tsx
useEffect(() => {
  void loadOrders();
}, [loadOrders]);
```

단순히:

``` text
useEffect니까 API 호출한다.
```

라고 이해하는 것이 아니라:

``` text
컴포넌트가 렌더링된다.
↓
Effect가 외부 시스템과 동기화를 수행한다.
↓
loadOrders()를 통해 주문 데이터를 가져온다.
↓
데이터를 State에 반영한다.
↓
State 변경으로 컴포넌트가 재렌더링된다.
↓
새로운 주문 데이터가 UI에 나타난다.
```

라고 설명할 수 있는 것이 목표다.

> **팁:** Day 24의 핵심 질문은 **왜 이 작업이 render가 아니라 Effect여야
> 하는가?**이다.
