# Day 24 問題・正解・解説 --- 日本語

> **選択肢は 4 問すべて正解。** ただし、問題 4 の理由には補足が必要。

## 問題 1 --- render 中の API 呼び出し

``` tsx
function OrdersPage() {
  const [orders, setOrders] = useState([]);
  loadOrders();
  return <OrderList orders={orders} />;
}
```

**質問：** どのような問題が起こり得るか？ - ① render のたびに API
を呼び、state 更新で再レンダリングが繰り返され得る。 - ② React
では普通の関数を呼べない。 - ③ `useState` は API データを保存できない。

**提出した答え：** ①
／理由：再レンダリングが繰り返される可能性があるから。

**判定：正解。** **詳しい理由：**
`loadOrders → setOrders → 再レンダリング → loadOrders`
の循環が発生し得る。render は純粋であるべき。ただし、すべての state
更新が必ず無限ループになるわけではない。

**コツ：** API 呼び出しから state 更新、次の render まで追跡する。

## 問題 2 --- `[userId]` の依存関係

``` tsx
useEffect(() => { fetchOrders(userId); }, [userId]);
```

**質問：** `userId` が 1 から 2 に変わったら？ - ① Effect
は再実行されない。 - ②
コミット後に再実行され、新しいユーザーの注文を取得する。 - ③
コンポーネントが必ず削除される。

**提出した答え：** ② ／理由：コミット後に再実行され、`userId`
が依存配列にあるから。

**判定：正解。** **補足：** React は前回と今回の `userId` を `Object.is`
で比較する。依存配列は値を Effect
に「渡す」のではなく、**参照するリアクティブな値を宣言する**もの。

**コツ：** 依存配列は再同期の条件を表す。

## 問題 3 --- 関数の参照

``` tsx
const loadOrders = async () => {
  const res = await fetch("/api/orders");
  setOrders(await res.json());
};
useEffect(() => { void loadOrders(); }, [loadOrders]);
```

**質問：** API 呼び出しが繰り返される可能性がある理由は？ - ① Effect
内で async 関数を呼ぶこと自体が間違いだから。 - ② render のたびに
`loadOrders` が新しい関数になるから。 - ③ state が配列だから。 - ④
依存配列が関数を自動メモ化するから。

**提出した答え：** ②
／理由：毎回新しい関数が作られ、依存値が変化したと判定されるから。

**判定：正解。**
**補足：**「依存配列の外にあるから」ではなく、**コンポーネント本体でレンダリングごとに生成されるから**。Effect
内部に移すか、必要に応じて `useCallback` を使う。

**コツ：** 同じコードでも同じ関数オブジェクトとは限らない。

## 問題 4 --- Effect とイベントハンドラー

**A：** 注文履歴ページの表示時に注文を取得。 **B：**
キャンセルボタンをクリックしたときに注文をキャンセル。 - ① 両方 Effect -
② A は Effect、B はイベントハンドラー - ③ A はイベントハンドラー、B は
Effect - ④ 両方 render 中に実行

**提出した答え：** ② ／理由：A は外部から受信し、B は送信するから。

**判定：選択肢は正解。理由は要修正。**

**なぜ不十分？** GET もクリックから実行でき、Effect
がデータを送信することもある。「受信か送信か」は判断基準ではない。

**模範解答：** A はページ表示や `userId`
の変更に合わせて注文データを同期するため Effect が適切。B
はユーザーの明示的なクリックがきっかけなのでイベントハンドラーが適切。

**コツ：** **何が処理を開始させたのか**で判断する。

## 最終評価

-   選択肢の正解：**4/4**
-   理解できている点：再レンダリングの循環、依存配列、関数参照
-   復習の優先事項：**問題 4 --- 実行のきっかけと HTTP の向きの違い**
-   次の課題：注文取得 Effect に `AbortController`、loading、error
    を追加する。

**覚え方：** `render = UI の計算` · `Effect = 外部との同期` ·
`event handler = ユーザー操作への応答`。
