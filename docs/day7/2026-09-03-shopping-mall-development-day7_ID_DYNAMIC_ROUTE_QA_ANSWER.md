# Day 7 --- `[id]` 개발자 셀프 체크 Q&A 정답

> 먼저 `DAY7_ID_DYNAMIC_ROUTE_QA.md`의 마지막 **개발자 셀프 체크**에
> 직접 답한 뒤 확인하세요.

------------------------------------------------------------------------

## Q1. 왜 `orders/id`가 아니라 `orders/[id]`인가?

### 답변

`orders/id`는 URL이 `/orders/id`로 고정되지만, `orders/[id]`는 해당
위치에 주문마다 다른 값을 받을 수 있기 때문입니다.

``` text
/orders/1001
/orders/1002
/orders/1003
```

> **팁**
>
> 대괄호가 있는지 없는지가 **static segment와 dynamic segment**를
> 구분합니다.

------------------------------------------------------------------------

## Q2. 주문이 100개여도 `[id]/page.tsx` 하나로 가능한 이유는?

### 답변

`[id]`가 URL의 변화하는 부분을 대신 받기 때문입니다. 페이지 파일은
하나지만 URL parameter 값은 주문마다 달라질 수 있습니다.

> **팁**
>
> 페이지 파일을 데이터 개수만큼 만드는 것이 아니라 **하나의 페이지에
> 서로 다른 데이터를 넣어 렌더링한다**고 생각하세요.

------------------------------------------------------------------------

## Q3. `[id]`와 `useParams()`의 역할 차이는?

### 답변

``` text
[id]
→ URL에서 값이 변할 위치를 정의

useParams()
→ 현재 URL에서 그 위치에 들어온 실제 값을 읽음
```

> **팁**
>
> `[id]` = 구조, `useParams()` = 값 읽기입니다.

------------------------------------------------------------------------

## Q4. `/orders/123`의 `123`은 무엇을 의미하는가?

### 답변

현재 보고자 하는 주문을 식별하기 위한 URL parameter입니다.

Day 7에서는 이 값을 `Order.id`와 연결합니다.

> **팁**
>
> `123` 자체가 주문 객체는 아닙니다. 주문을 찾기 위한 **식별값**입니다.

------------------------------------------------------------------------

## Q5. URL id를 왜 `number`로 변환할 수 있는가?

### 답변

현재 프로젝트의 `Order.id`가 `number` 타입이기 때문입니다.

URL에서 읽은 `"123"`과 숫자 `123`을 strict equality로 비교하면:

``` ts
"123" === 123
// false
```

가 되므로 필요하면 `Number(...)`로 타입을 맞춥니다.

> **팁**
>
> 비교하기 전에 **양쪽 타입이 같은가?**를 확인하는 습관을 들이세요.

------------------------------------------------------------------------

## Q6. `find()`는 어떤 데이터를 대상으로 무엇을 찾는가?

### 답변

`localStorage`에서 불러온 `Order[]`를 대상으로 URL id와 같은
`order.id`를 가진 주문 하나를 찾습니다.

``` tsx
orders.find((order) => order.id === orderId)
```

> **팁**
>
> `map()`은 전체 처리, `find()`는 조건에 맞는 하나 찾기입니다.

------------------------------------------------------------------------

## Q7. `[id] → useParams() → find()`를 순서대로 설명하면?

### 답변

``` text
[id]
동적인 URL 자리 생성
↓
/orders/123
실제 URL
↓
useParams()
123 읽기
↓
필요하면 타입 변환
↓
find()
Order[]에서 id가 같은 주문 검색
↓
Order 하나
↓
상세 UI 출력
```

즉:

> **`[id]`로 URL의 동적인 자리를 만들고, `useParams()`로 주문 ID를 읽은
> 다음, `find()`로 저장된 주문 중 해당 ID의 주문 하나를 찾는다.**

> **팁**
>
> 이 마지막 문장을 코드 없이 자연스럽게 설명할 수 있으면 Day 7의 Dynamic
> Route 개념을 이해한 것입니다.
