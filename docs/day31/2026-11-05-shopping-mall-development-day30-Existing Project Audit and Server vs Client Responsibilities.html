Day 31 — 문제·답변

기존 프로젝트 점검과 Server / Client 구분

학습일: 2026-11-05 | 계획 학습 시간: 120 min | Score: 94/100 (PASS)

1. Route Handler와 Client Component의 차이는?

정답 B: Route Handler는 HTTP 요청·응답을 처리하고 Client Component는 사용자 상호작용을 담당한다. 실제 제출 정답 B, 20/20점.

2. 서버에서 localStorage를 읽으면 왜 안 되는가?

서버에는 브라우저 localStorage가 존재하지 않는다.

3. "use client"면 모든 코드가 브라우저에서만 실행되는가?

아니다. 초기 서버 프리렌더링이 가능하므로 렌더링 중 브라우저 API 접근에 주의한다.

4. useSyncExternalStore의 목적은?

외부 저장소 구독 및 서버/클라이언트 스냅샷 관리.

5. 주문 스냅샷이 필요한 이유는?

상품명과 가격이 나중에 바뀌어도 주문 당시 정보를 보존하기 위해서다.

6. storage 이벤트가 같은 문서에서 발생하는가?

변경을 수행한 문서에는 발생하지 않는다. 별도 사용자 정의 이벤트를 활용한다.

7. 관리자 주문과 사용자 주문은 연결되어 있는가?

현재 확인한 코드에서는 연결되어 있지 않다. 관리자 API 경로 파일도 없다.

8. 주문 완료 페이지의 한계는?

orders[orders.length - 1]은 마지막 저장 주문이지 반드시 방금 완료한 주문은 아니다.

Tip / 팁 / コツ: 실행 위치와 데이터 저장 위치를 먼저 확인하세요.

문제

export default function CartPage() {
  const cart = JSON.parse(localStorage.getItem("cart") ?? "[]");
  return <p>상품 종류: {cart.length}</p>;
}

요구사항

  • "use client" 선언
  • 기존 useCartStorage Hook 재사용
  • 렌더링 중 localStorage 직접 접근 금지
  • SSR·하이드레이션 고려

제출한 코드

"use client";

import { useCartStorage } from "@/hooks/useCartStorage";
import { CartItem } from "@/types/cart";

export default function CartPage() {
  const cart = useCartStorage();
  const updateCart = (updatedCart: CartItem[]) => {
    localStorage.setItem("cart", JSON.stringify(updatedCart));
    window.dispatchEvent(new Event("cart-updated"));
    updateCart(updatedCart);
  };

  return <p>상품 종류: {cart.length}</p>;
}

채점 및 피드백

24 / 30 — 5/5 + 10/10 + 5/5 + 4/10

사용하지 않는 updateCart 함수가 자기 자신을 종료 조건 없이 호출한다. 현재 호출되지 않아 즉시 오류는 발생하지 않지만, 호출 시 스택 초과가 발생할 수 있다. 미사용 함수와 import도 제거한다.

수정된 정답

Day 31 — 総まとめ

既存プロジェクトの点検とServer / Clientの区別

学習目標

Next.js App Routerのコンポーネント境界とECサイトの注文データフローを理解する。

重要な概念

Server Component

サーバー側のデータ取得とレンダリング。App Routerの既定。

Client Component

"use client"境界。イベント、Reactの状態、ブラウザAPIを扱う。

Route Handler

app/api/**/route.tsでGET・POST・PATCHを処理。

useSyncExternalStore

外部ストアを購読し、SSRとハイドレーションのスナップショットを管理。

ファイル別の責務

  • app/cart/page.tsx
  • app/checkout/page.tsx
  • app/order-complete/page.tsx
  • app/orders/page.tsx
  • app/orders/[id]/page.tsx
  • src/hooks/useCartStorage.ts
  • src/hooks/useOrdersStorage.ts
  • app/admin/orders/hooks/useOrders.ts

注文データの流れ

  1. 商品データ(products.ts)を参照
  2. カートをlocalStorage["cart"]から取得
  3. チェックアウトでname・price・quantityのスナップショットを作成
  4. localStorage["orders"]へ保存しorders-updatedを通知
  5. カートを削除してcart-updatedを通知
  6. 注文完了ページへ遷移
  7. 注文履歴・詳細の表示とキャンセル

発見した課題

管理者APIのRoute Handlerが2件存在せず、ユーザーの注文はブラウザのlocalStorageに保存されます。

改善項目

  • 管理者APIと共通サーバーストレージの設計
  • 注文IDによる完了ページの表示
  • チェックアウト時のJSON例外処理
  • カートの読み込み状態の明確化
  • サーバー側の権限と注文状態の検証

Day 31 — 問題・解答

既存プロジェクトの点検とServer / Clientの区別

学習日: 2026-11-05 | 予定学習時間: 120 min | Score: 94/100 (PASS)

1. Route HandlerとClient Componentの違いは？

正解B：Route HandlerはHTTPリクエストを処理し、Client Componentはユーザー操作を担当。提出解答B、20/20点。

2. サーバーでlocalStorageを読めない理由は？

サーバー環境にブラウザのlocalStorageが存在しないため。

3. "use client"ならブラウザだけで実行される？

いいえ。初期HTMLがサーバーでレンダリングされる場合もある。

4. useSyncExternalStoreの目的は？

外部ストアの購読とサーバー／クライアントのスナップショット管理。

5. 注文スナップショットが必要な理由は？

商品情報の変更後も購入時の名前や価格を保持するため。

6. storageイベントは変更元の文書にも届く？

届かないため、独自イベントを併用する。

7. 管理者とユーザーの注文データは連携している？

確認した実装では未連携。管理者APIのファイルも存在しない。

8. 注文完了ページの課題は？

配列の最後の注文は必ずしも直前に完了した注文ではない。

Tip / 팁 / コツ: 実行環境とデータの保存場所を先に確認しましょう。

Learning objective

Understand component boundaries in Next.js App Router and trace e-commerce order data.

Core concepts

Server Component

Default App Router component; supports server-side data access and rendering.

Client Component

"use client" boundary for events, React state, and browser APIs.

Route Handler

Handles GET, POST, PATCH in app/api/**/route.ts.

useSyncExternalStore

Subscribes to external stores with SSR and hydration snapshots.

File responsibilities

  • app/cart/page.tsx
  • app/checkout/page.tsx
  • app/order-complete/page.tsx
  • app/orders/page.tsx
  • app/orders/[id]/page.tsx
  • src/hooks/useCartStorage.ts
  • src/hooks/useOrdersStorage.ts
  • app/admin/orders/hooks/useOrders.ts

Order data flow

  1. Read product data from products.ts
  2. Read cart from localStorage["cart"]
  3. Create order snapshots of name, price, and quantity
  4. Save to localStorage["orders"] and dispatch orders-updated
  5. Clear cart and dispatch cart-updated
  6. Navigate to order completion
  7. Display history/details and handle cancellation

Key findings

Two admin API Route Handlers are missing, while customer orders are stored in browser localStorage.

Improvement backlog

  • Design admin API and shared server-side persistence
  • Use order IDs on the completion page
  • Handle malformed JSON at checkout
  • Expose a distinct cart readiness state
  • Validate authorization and order state server-side

Day 31 — Questions & Answers

Existing Project Review and Server / Client Boundaries

Date: 2026-11-05 | Planned study time: 120 min | Score: 94/100 (PASS)

1. What distinguishes a Route Handler from a Client Component?

Correct answer B: Route Handlers process HTTP requests; Client Components handle interactions. Submitted B, 20/20.

2. Why not read localStorage on the server?

The browser localStorage API does not exist in the server environment.

3. Does "use client" mean browser-only execution?

No. Client Components may be pre-rendered on the server.

4. Why use useSyncExternalStore?

To subscribe to external stores with server and client snapshots.

5. Why snapshot order items?

To preserve names and prices as they were when the order was placed.

6. Does the storage event fire in the writing document?

No. A custom event can notify listeners in the same document.

7. Are customer and admin orders connected?

Not in the inspected code. The admin API files are also missing.

8. What is the order completion page limitation?

The last array element is not necessarily the order just completed.

Tip / 팁 / コツ: Identify where code runs and where data is stored before making changes.
