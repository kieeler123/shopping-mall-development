Day 28 — Data Flow and State Updates: Complete Review

Review based on the actual order-management project · Next.js / React / TypeScript

1. Separation of responsibilities

useOrders exposes orders, isLoading, error, and updateOrderStatus. AdminOrdersPage calls the hook and passes order and onStatusChange to OrderCard. OrderCard calls the callback from its select change handler.

Study tip: Identify who owns data, who renders it, and who requests a change.

2. One-way data flow

A parent passes values down through props. A child does not mutate parent state; it invokes a callback passed by the parent.

Study tip: onStatusChange={updateOrderStatus} passes a function; adding () invokes it during rendering.

3. Immutable updates

setOrders(prev => prev.map(order => order.id === updatedOrder.id ? updatedOrder : order)) creates a new array and replaces only the matching order with the server response.

Study tip: map creates a new array but unchanged object references are reused.

4. API and errors

PATCH /api/orders/{id}, check response.ok, parse updatedOrder, then update state and return the Order. On failure, set an error and return null.

Study tip: fetch does not reject merely because the server responds with HTTP 4xx/5xx.

5. TypeScript

The hook signature is (id: number, status: OrderStatus) => Promise<Order | null>. A void-returning callback prop can accept a function whose return value is ignored; specify Promise when the child needs to handle the result.

Study tip: Check for null after awaiting Promise<Order | null>.

6. Controlled input

OrderCard uses select value={order.status}. The selected value reflects props, and updates after the PATCH succeeds and setOrders supplies new props.

Study tip: Explain the full server-to-UI synchronization sequence.

7. UX caveats

A PATCH error sets error, so the !error condition in AdminOrdersPage hides all order cards. There is also no separate PATCH pending state or duplicate-request prevention.

Study tip: Separating load errors from mutation errors is a possible future improvement, not a required Day 28 refactor.

8. Corrections from today

Use backticks for interpolated URLs, check commas in fetch options, keep setter names consistent, and convert caught unknown errors to strings before calling setError.

Study tip: Proofread URL, commas, names, and types.

Actual execution flow

AdminOrdersPage → OrderCard → onStatusChange → updateOrderStatus → PATCH API → response.ok → updatedOrder → setOrders(map) → React render
