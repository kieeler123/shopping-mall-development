> **中心となる問い：** データが存在するかどうか以外に、UIにはどのような状態があるのか？

- **技術スタック：** Next.js · React · TypeScript

> **ヒント：** 4つの状態の名前を暗記するだけでなく、それぞれの成立条件を文章で説明してみよう。

## 2. UI状態の基本モデル

```text
リクエスト開始
  ↓
Loading
  ├─ 失敗 → Error
  └─ 成功
      ├─ データなし → Empty
      └─ データあり → Success
```

| 状態 | 条件 | UI |
|---|---|---|
| Loading | リクエスト処理中 | 注文を読み込み中です... |
| Error | リクエスト失敗 | エラーメッセージ |
| Empty | 成功、注文0件 | 注文がありません。 |
| Success | 成功、注文1件以上 | 注文カード一覧 |

> **ヒント：** このモデルは**一覧取得**を基準にしている。注文状態の更新（PATCH）中や再試行中など、別のUI状態も考えられる。

### Step 3 — 条件付きレンダリング（15分）

```tsx
{isLoading && <p>注文を読み込み中です...</p>}
{error && <p>エラー: {error}</p>}
{!isLoading && !error && orders.length === 0 && (
  <p>注文がありません。</p>
)}
```

- `&&`、論理否定`!`、厳密等価`===`を理解する。
- 必要に応じて三項演算子での表現と比較する。
- **四択問題：** `!isLoading && !error`はどのような状況を表すか？

> **ヒント：** 各条件を`true`または`false`に置き換えて計算してみよう。

### Step 4 — UI状態の優先順位（15分）

- LoadingとErrorが同時に真なら、画面表示が重複する可能性を理解する。
- `if`と早期returnで優先順位を明確にする。
- UI状態を1つの値で表す方法も概念的に比較するが、新しいライブラリは導入しない。
- **四択問題：** LoadingとErrorが同時に存在するとき、画面をどう扱うべきか？

> **ヒント：** ユーザーに最初に伝えるべき状態を決めてから条件を書こう。

## 6. Step 1の開始問題

次のコードを見て答えよう。

```tsx
const { orders, isLoading, error } = useOrders();
```

**問題1.** `useOrders()`内で`setOrders()`を使って注文配列を変更すると、なぜReactのUIが更新されるのか？

- A. `fetch()`が自動的にHTMLを書き換えるから。
- B. ReactがStateの変更に応じてコンポーネントを再レンダリングし、新しいPropsを渡すから。
- C. `OrderCard`がサーバーから直接データを再取得するから。
- D. `useEffect()`がStateの変更のたびに自動でAPIを呼び出すから。

**正解：** B

**解説：** ReactがState更新を処理すると関連コンポーネントが再レンダリングされ、更新された`orders`から生成された新しいPropsが`OrderCard`に渡される。

> **ヒント：** 実際に解くときは、先に正解を隠して挑戦しよう。
